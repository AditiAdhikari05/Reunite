How this runs on IBM LinuxONE

DisasterBridge runs on IBM LinuxONE, a Linux server built on the IBM Z mainframe architecture (s390x). Sensitive reports are stored and matched on the server, not in anyone's browser.

What happens to a report

  1. A family sends a report from this website. It goes straight to the Flask application on LinuxONE.
  2. Authorities add people who have been found. Only staff with an access code can do this, and the server checks the code on every request.
  3. The matching engine runs on the same LinuxONE server. It compares reports and suggests possible matches, each with a score and its reasons.
  4. A trained person checks every suggestion and confirms or rejects it. The software never confirms a match by itself.
  5. Families only ever see one of three statuses: Searching, Possible match under review, or Reunited. Details about found people stay on the server.

Why LinuxONE

Disaster data is personal and sensitive. Keeping storage, matching and the website on one secure server means fewer copies of the data and fewer places it can leak. The app uses plain Python and static web pages, so it runs on s390x without any special build tools.
